# Сборка Russian Roulette 2 (nw205PeopleWater) в Docker

Исходная система сборки (Watcom C/C++ 10.6 + Turbo Assembler + препроцессор angel,
рекурсивные wmake + BAT-файлы) сохранена без портирования. Docker-обёртка лишь
воссоздаёт окружение `C:\NW`, которое ожидают make-файлы.

Состав:
- `Dockerfile`   — образ: wine + Open Watcom 2.0 (открытая замена Watcom 10.6).
- `build.sh`     — основная сборка игры в контейнере (только Watcom: C/C++ + линковка).
- `nw-asm-wine`  — отдельный скрипт для ассемблерных файлов (.asm/.ang), запускается
                   на хосте, требует wine + Borland TASMX 4.1. Ассемблерные файлы
                   не редактируются, поэтому их достаточно собрать один раз.
- `bin/`         — обёртки: watcom-инструменты через wine, angelmasm через wine.
- `nw-build`     — bash-репликация цепочки BAT (TOREL/TODEB → MAKEALL → LINK → DESIGN.LIB),
                   исполняется внутри контейнера.

## 1. Один раз: ассемблерные объектники (nw-asm-wine)

TASM в образ не входит. Понадобится Borland **TASM32.EXE/TASMX.EXE**
(Turbo Assembler 4.1). Положите бинарник в `docker/tasm/` (или задайте
TASM_EXE) и выполните:

    docker/nw-asm-wine both   # соберёт docker/asm-obj/{WR,WD}/*.obj

(нужен wine на хосте; DOS-варианты TASM запускаются через встроенный dosbox
wine, Win32-вариант — напрямую). Скрипт прогоняет 13 чистых .asm через TASM
и 7 файлов .ANG через angelmasm.exe → .ASX → TASM. Повторно нужен только
после `build.sh --clean` или удаления OBJ/.

## 2. Сборка игры (docker)

    docker/build.sh release   # → OUTPUT/gameWR.exe
    docker/build.sh debug     # → OUTPUT/gameWD.exe
    docker/build.sh release --clean   # с очисткой obj/ и .lib

Первый запуск собирает образ (~5 минут, скачивает Open Watcom 2.0 с GitHub).
Исходники монтируются как `C:\NW` — make-файлы работают без правок.

## Что было адаптировано под Open Watcom 2.0 (шеймы, исходники почти не тронуты)

- Dockerfile распаковывает win-хостовую сборку OW2 (установщик — обычный ZIP);
  инструменты запускаются через wine, поэтому make-файлы видят `C:\NW`, `C:\WATCOM`.
- `nw-build` при старте убирает из make.inc флаг `-7` (в OW2 его нет) и
  `-wx -we` в debug (OW2 выдаёт новые предупреждения W836/W731/W716, которые
  этими флагами становились ошибками).
- Убран байт DOS EOF (0x1A) из ~12 файлов, читаемых компилятором
  (cpp/h/inl/make/rsp). В .asm/.ang/инклюдах TASM байты сохранены.
- Три Debug-бага, которые прощал Watcom 10.6 (необъявленная переменная цикла,
  используемая после цикла): `VIEW/FIGURE.CPP`, `VIEW/TERRAIN4.INL` (7 мест),
  `BRIEFING/MAPCHNNL.CPP` (2 места) — добавлены объявления переменных.
  На release-конфигурацию эти правки не влияют.

## Итоговая архитектура сборки (проверена)

Полная сборка release работает: `docker/build.sh release --clean` → OUTPUT/gameWR.exe
(PE32 GUI, Win32). Состав инструментария:

- компиляторы/wmake/wlib — Open Watcom 2.0 (встроены в образ, C:\OW2);
- линкер — **wlink из CI-снапшота OW2** (`/opt/owsnap/binl64/wlink`, нативный
  linux-бинарник): только он знает `system nt_win` — у wlink из установщика
  Current-build таблица систем сломана (W1107/E3002);
- нюанс: wlink читает `wlink.lnk` (в нём определён `nt_win`) из ТЕКУЩЕГО
  каталога — nw-build копирует его в OBJ/WR перед линковкой;
- ассемблер — Borland TASMX 4.1 через `nw-asm-wine` (хост, один раз);
- `docker/watcom106/` больше не требуется для сборки (каталог можно не
  заполнять).

Шимы в nw-build: `-7`, `-wx -we` из make.inc (не существуют/ломают OW2);
`-bm` (reentrant clib — у статического clib OW2 нет нужных символов);
убран DOS EOF (0x1A) и CR в make.inc/.rsp; авто-зависимости (.AUTODEPEND)
сняты с asm-правил (wmake 10.6 не понимает чужие OMF); LIBPATH дополнен
каталогами библиотек OW2 (libp у wlink замещает пути по умолчанию).

ящего Watcom 10.6 (рекомендуется)

Readme исходников прямо указывает на Watcom 10.6. Скопируйте установленный
Watcom 10.6 (Windows-хост) в `docker/watcom106/` — ожидается хотя бы
`binnt/wpp386.exe` (+ `h/`, `lib386/nt/` с ddraw.lib и uuid.lib). Entrypoint
сам предпочтёт его встроенному Open Watcom 2.0; при этом решается и проблема
линковки TASM-объектников (wlink из OW2 их не принимает, 10.6 — принимал).

## Статус debug-сборки

`build.sh debug` компилирует все модули, но финальная линковка падает: дебаг-объектники
ARENA ссылаются на методы (SFMatrix3x4::Rotate*, DebugAssertionFailedD и др.),
которых нет в `DESIGN.LIB/SRC` — исходники DESIGN.LIB не полностью соответствуют
заголовкам (оригинальный workflow опирался на предсобранную designwr.lib).
Это ограничение исходников, не сборки.

## Ограничения / риски

- Readme исходников предупреждает, что Watcom 11 даёт неработающий exe.
  Open Watcom 2.0 — развитие 11-й ветки, поэтому работоспособность собранного
  exe нужно проверить в игре (сборка и линковка проходят полностью).
- Линковка проверена до чтения объектных файлов; для полного end-to-end
  нужны настоящие TASM-объектники (шаг 1).
- Если TASM недоступен, можно один раз собрать ассемблерные .obj в исходном
  окружении (DOS/Windows) и просто скопировать их в obj/wr и obj/wd.

## Вариант ассемблера

Единственный используемый вариант — `nw-asm-wine` (см. раздел 1). Осторожно
с выбором бинарника: `tasmx.exe` от Squak Valley Software («TASM 3.1,
Table Assembler») — это другой продукт для микроконтроллеров, x86-код игры
он не собирает. Проверка: запустите бинарник без аргументов под wine —
Borland печатает «Turbo Assembler Version».
